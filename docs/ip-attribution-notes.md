# IP 归属地插件维护笔记

记录每个 App 的实测结论、为什么留/不留某条规则，以及怎么改规则。规则本体在
`Loon.conf` 的「IP 归属地伪装」区块和 `plugin/ip-attribution.plugin` 里，两边都由
`scripts/sync-anti-ip-rules.ps1` 生成。

## 两个产物怎么选

| 产物 | 策略写法 | 适用 | 限制 |
|---|---|---|---|
| `Loon.conf` 本地 `[Rule]` 区块 | 具体策略组 `IP归属地` | 自己用，优先级最高 | 要手工贴进配置，且必须在 `GEOIP,CN,DIRECT` 之前 |
| `plugin/ip-attribution.plugin` | `PROXY` | 一条 `loon://import` 挂到任何配置 | 优先级低于对方本地规则，IP 规则可能被对方 `GEOIP,CN` 抢先直连 |

域名规则不受 `GEOIP,CN` 影响，两个产物的域名部分效果一样。

## 规则怎么读

- 按 App 分组（`# ===== 哔哩哔哩（25 条）=====`），组内顺序照抄上游，组间顺序也照抄上游。
- 规则从上往下匹配、命中即停，**组内顺序有意义，不要重排**。
- 三种策略：
  - `REJECT`：阻断 App 私有 HTTPDNS。不拦的话 App 拿着 IP 直连，域名分流整个失效。
  - `DIRECT`：视频 / 图片 / 静态资源 CDN。这些走代理只会变慢，不影响属地。
  - `PROXY` / `IP归属地`：真正决定属地的业务接口。
- 「本仓库补丁」段排在所有上游分组之后。`-normal-` 这种宽泛关键词必须最后生效，
  放前面会抢走其它 App 的流量。

## 案例：懂球帝 —— 服务端不收海外 IP

上游写的是 `DOMAIN-SUFFIX,dongqiudi.com`，少了个 "an"。懂球帝 App 实际用
`dongdianqiu.com`（抓包证据：请求参数带 `app=dqd`，响应体里有「懂球帝,App,手机客户端」，
用户数据里有 `img1.dongdianqiu.com` 的头像），所以上游那条一条都没匹配上，231 条请求全部直连。

但代理这条路走不通，实测两次：

1. 整段代理 `dongdianqiu.com` → 打开 App 就报网络超时；
2. 只代理 `api.dongdianqiu.com` → 下拉刷新仍超时；
3. 把 `IP归属地` 切回 `DIRECT` → 立刻恢复正常；
4. 换成非美国节点再试 → 仍然超时。

结论：服务端不接受海外 IP。不要再为它加规则。

## 案例：B站主页 IP 属地 —— 账号级属性，规则改不动

同一账号在 B站 有两套属地：

- 评论区 / 动态 / 投稿：按「最近一次发布内容、评论时的网络位置」实时算，跟着节点走。
- 个人主页的「IP属地」：账号级属性，服务端按常用登录地汇总，跟当前这次请求的 IP 无关。

同类对比：抖音 / 小红书 的主页属地是按「近期发布内容」算的，换节点后很快就变（实测抖音主页几分钟内
就是节点国家）；B站 主页是「常驻地」，要滞后几周。所以「抖音主页已经变了、B站 主页还是原地」
是产品逻辑差异，不是规则没生效。

依据：

1. [B站客服答疑](https://www.bilibili.com/v/topic/detail?topic_id=45799)（2022-07-25）：
   信息发布页展示的是最近一次发布内容 / 评论时的网络位置；账号 IP 属地另行计算。
2. [V2EX 2025-10 同现象](https://www.v2ex.com/t/1163663)：开全局代理发完评论，主页 IP 依旧不动；
   回复里说「评论有评论的 ip，账号页面是常用归属地」「主页 IP 一般要十天以上变」。
3. 主页属地由 App 端 `app.bilibili.com/x/v2/space` 返回，本来就被
   `DOMAIN-SUFFIX,bilibili.com` 覆盖，请求确实走了节点，所以不是分流问题。
4. 2026-10-18 抓包实证：`app.bilibili.com/x/v2/space` 走的是香港节点（`默认代理 ▶ 自动优选 ▶ 🇭🇰 香港S01`），
   响应里 `space_tag` 仍然写着 `IP属地：河南` —— 出口在境外，返回值还是国内，说明这个字段是服务端存的，
   跟这次请求的 IP 无关。
5. 同一天第二次抓包（美国节点）三条同时成立，基本可以定案：
   `POST api.bilibili.com/x/v2/reply/add` 返回 `"reply_control":{"location":"IP属地：美国"}`（刚发的评论），
   `GET app.bilibili.com/x/v2/space` 仍返回 `IP属地：河南`（主页），
   而网易云 CDN 的 `cdn-user-ip` 是节点 IP `161.114.115.168`（美国洛杉矶 Yunyoo）、
   懂球帝的 `x-request-ip` 是真实 IP `42.234.47.14`（河南郑州联通）。

社区实测的刷新周期（都比「评论实时变」慢得多）：

- [V2EX](https://www.v2ex.com/t/1163663)：「账号页面是常用归属地」「主页 IP 一般要十天以上变」；
- [B站视频 BV1wXonY7E2Z](https://www.bilibili.com/video/BV1wXonY7E2Z)：个人主页 IP 刷新大约要 **3 周**；
- [B站视频 BV1uy411B7u2](https://www.bilibili.com/video/BV1uy411B7u2)：描述里写「个人空间大概 **一个月** 后
  才会变成新地方」，并解释了「动态/评论立刻变、个人空间滞后」的原因。

没有能「立刻改」的接口，能做的是让服务端尽快把「常驻地」算成境外：

1. **固定一个国家**：`IP归属地` 组别选「默认代理」或「自动优选」，它们会在香港、美国之间跳
   （2026-10-18 两次抓包，一次出口香港、一次是美国洛杉矶），常驻地永远收敛不了。
2. 在节点下**退出登录、重新登录一次**，把登录记录写成境外 IP（有概率立刻生效，成本低，值得先试）。
3. 之后**连续 3–4 周**每天正常用，别换节点、别切回直连——直连一次就会写一条国内记录。
4. 验证：App「我的 → 设置 → 账号安全 → 登录记录」看最近登录是不是节点 IP；主页看 `space_tag` 的
   `IP属地` 有没有变。

频繁退出重登会触发风控（验证码、人脸），一天一次都算多。

## 改规则的流程

现在的 `Loon.conf` 故意不放本地区块（本地规则优先级高于插件，会把插件的 IP 规则抢先直连），
所以主产物只有插件，补丁规则单独放在 `plugin/app-patches.conf`。

1. 要补规则就改 [`plugin/app-patches.conf`](../plugin/app-patches.conf)：只加业务接口域名，
   CDN / 静态资源不要加；宽泛关键词必须放最后。文件里的策略直接写 `PROXY` / `DIRECT` / `REJECT`。
2. 跑同步脚本（建议 pwsh 7；Windows PowerShell 5.1 需要 `-ExecutionPolicy Bypass`，
   且脚本是无 BOM 的 UTF-8，5.1 会按 ANSI 读成乱码）：

   ```powershell
   pwsh -File scripts/sync-anti-ip-rules.ps1
   ```

   脚本会拉取上游 `rules.yaml`，重新生成 `plugin/ip-attribution.plugin`；
   如果传入的 `Loon.conf` 里有 `# ==== IP 归属地伪装` 标记，才会额外重写本地区块。
   重复运行结果一致。
3. 看输出：规则总数、分组数、三个策略各多少条。上游改版导致解析异常时脚本会直接中止，
   不会写坏配置。
4. 提交推送后，Loon 里重新拉一次插件（或删掉重加）：配置里的地址是
   `https://raw.githubusercontent.com/okgutta/loonout/main/plugin/ip-attribution.plugin`。
